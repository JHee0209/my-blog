자바에서 변수를 만들 때는 정수 하나를 담더라도 byte, short, int, long 중에 골라야 한다.

## 이게 없으면 뭐가 불편할까

변수는 값을 담는 상자다. 그런데 상자에 넣을 값이 정수인지, 실수인지, 문자인지, 참/거짓인지 미리 정해두지 않으면 어떻게 될까.

컴퓨터는 모든 값을 그냥 숫자(비트)로 저장한다. 그 숫자를 정수로 읽을지, 문자로 읽을지, 소수점이 있는 실수로 읽을지는 저장할 때 정해둔 종류에 따라 달라진다. 이 종류를 미리 정해두지 않으면 컴퓨터는 메모리에 저장된 값을 어떻게 해석해야 할지 구분하지 못한다.

## 한 문장으로 말하면

자료형은 변수에 담을 값의 종류와, 그 값이 메모리에서 차지할 크기를 미리 정해두는 것이다.

자료형은 그릇과 비슷하다. 종지에는 간장을 담고 냄비에는 국을 담듯이, 담을 값의 종류와 양에 맞는 그릇을 고르는 것과 같다. 다만 이 비유에는 한계가 있다. 그릇은 크기만 다르지만 자료형은 크기뿐 아니라 담는 값의 종류(정수, 실수, 문자, 논리)도 다르다.

## 직접 해보기

오늘 연습한 코드로 정수형과 실수형을 각각 선언해봤다.

```java
// 숫자형 - 정수를 담는 자료형
byte b = 10;    // 1 byte (표현 범위: -128 ~ 127)
short s = 10;   // 2 byte
int i = 10;     // 4 byte
long l = 10;    // 8 byte

// 숫자형 - 실수를 담는 자료형
float f = 3.14f;    // 4 byte, 뒤에 f를 붙여 float임을 표시한다
double d = 3.14;    // 8 byte
```

정수형 네 개(byte, short, int, long)는 전부 정수를 담는데도 크기가 다르다. 실수형도 float과 double 두 가지로 나뉜다.

## 헷갈렸던 점

처음에는 "왜 정수 담는 자료형이 이렇게 여러 개로 나뉘어 있을까"가 이해되지 않았다. int 하나로 통일하면 안 되는 걸까 싶었다.

자바 공식 튜토리얼을 찾아보니, 크기가 다른 이유는 두 가지였다.

- **메모리 절약** — 배열처럼 같은 자료형의 값을 대량으로 저장할 때, 작은 자료형을 쓰면 메모리를 아낄 수 있다.
- **코드로 의도를 드러냄** — 변수의 값 범위가 제한되어 있다는 사실 자체가 "이 값은 이 정도 크기를 넘지 않는다"는 문서 역할을 한다.

크기가 커질수록 표현할 수 있는 값의 범위도 넓어진다. 대신 메모리를 더 많이 차지한다.

| 자료형 | 크기 | 표현 범위 |
|--------|------|-----------|
| byte | 1 byte | -128 ~ 127 |
| short | 2 byte | -32,768 ~ 32,767 |
| int | 4 byte | -2³¹ ~ 2³¹-1 |
| long | 8 byte | -2⁶³ ~ 2⁶³-1 |

예를 들어 byte는 1바이트(8비트)만 쓰기 때문에 -128부터 127까지만 담을 수 있다. 이 범위를 넘는 값(예: 200)을 담으려면 short나 int처럼 더 큰 자료형을 써야 한다.

## 더 학습하면 좋은 개념

- **형변환(casting)** — 자료형끼리 크기가 다르면 값을 주고받을 때 데이터가 잘리거나 손실될 수 있다. byte에 int 값을 넣으면 무슨 일이 생기는지 알아야 한다.
- **오버플로우(overflow)** — 자료형이 담을 수 있는 범위를 넘는 값을 넣었을 때 어떻게 되는지 아직 안 해봤다. 크기 제한이 실제로 왜 중요한지 이해하는 데 필요하다.
- **래퍼 클래스(Wrapper class)** — int, double 같은 기본 자료형을 객체로 다뤄야 할 때(예: 컬렉션에 담을 때) 필요한 개념이다.
- **리터럴 접미사** — float에는 왜 f를 붙이고 long에는 L을 붙이는지, 이번 코드에서 본 `3.14f`와 연결되는 개념이다.
